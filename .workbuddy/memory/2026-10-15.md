## 攻击结算接入 buff（CardData / Unit / PlayerCardSystem / EnemyUnit）

用户问"按 buff 效果结算来看，CardData 里的攻击结算是否该改"——答案是必须改，发现 4 类"填了不生效"：

**核心 bug：trigger 查询与 BuffData 填写约定不一致（影响面最大）**
- BuffData 约定：影响类的属性效果统一填 `立即生效`
- Unit.cs 却按语义时机查：`受到伤害固定减免` / `受到伤害倍率` 查 `受到伤害时`，
  `攻击伤害加成` 查 `攻击时` → 三处永远返回 0，易伤/殊死一搏减伤/力量/无力全部失效
- 已统一改为按 `立即生效` 查询（`GetTotalEffectValue` 的默认参数就是它，直接省掉第二参数）

**CardData 新增"最终数值"区**（放在 `CanDefenseEnemy` 之后、`Resolve` 之前）：
- `IsMovementSkill` / `IsTeleportSkill`（按 CardTag.位移 / CardTag.传送 判定）
- `GetFinalDamage(caster)` = damage + 攻击伤害加成×层数，下限 0
- `GetFinalActionCost(caster)` = 攻击技能 actionCost × 攻击耐力消耗倍率，向上取整（防御技能不受影响）
- `GetEffectiveMaxRange(caster)` / `IsInEffectiveRange(...)` —— 位移类受移动距离加成修正，**传送类不修正**
- 设计原则：易伤/受到伤害减免归 `Unit.TakeDamage` 算，CardData 不重复乘（否则伤害翻倍）

**Resolve 改动**：
- 开头加"禁止行动"兜底（原先只有玩家侧 ValidateSlot 拦，敌人走 Resolve 是漏的）
- 伤害走 GetFinalDamage，日志打印真实伤害
- 打障碍物复用同一套伤害公式
- 加"亲密"禁打目标兜底

**PlayerCardSystem 改动**：
- 扣费改 `card.GetFinalActionCost(player)`
- 亲密校验拦在扣费之前（否则扣了耐力打不出去）
- IsInRange 用 GetEffectiveMaxRange；FindNearestEnemy 跳过被亲密禁止的单位

**EnemyUnit 改动**：ExecutePlannedSkills 射程校验改用 `card.IsInEffectiveRange(...)`，与玩家侧共用

**Unit 新增**：`IsAttackTargetForbidden(Unit)`，遍历自身 buff 查 BuffData.IsForbiddenAttackTarget

**给用户的两个提醒**：
- `ApplyBuff` 只在 `buffData.canStack == true` 时才加层数，而 `canStack` 默认 false、`maxStack` 默认 1。
  所以做 asset 时**中毒/灼烧/流血/残废/无力必须勾上 canStack 并把 maxStack 调大**，否则层数永远停在 1。
- 数值约定：倍率类填绝对乘数，加成/减免类填增量。

## 修复用户指出的 3 个问题（倍率叠加 / 死亡判定 / 攻击加成读取）

用户指出三处，全部核实属实并已修复：

**① 倍率型效果的层数叠加是错的（把乘数当增量相加）**
- 原实现一律 `total += effect.value * 层数` → 易伤 1.25 叠 2 层得 2.5 倍（凭空多出一倍基数）
- 修复：按类型区分
  - 加成型（力量/无力/殊死一搏）→ 数值直接累加，无 buff 时返回 0
  - 倍率型（易伤/力竭/虚弱/沉重）→ `1 + Σ(value-1)×层数`，无 buff 时返回 1，下限 0
- 分类器：新增 `BuffData.IsMultiplierType(BuffEffectType)` 静态方法（要加新倍率类型必须同步登记）
- `BuffData.GetTotalValue` 同步改倍率感知，trigger 参数改可空

**② Unit 缺少死亡判定**
- Unity `Destroy` 延迟到帧末，`Die()` 后对象还会被调用 → 会出现"给已死单位挂 buff"
- 修复：新增 `isDead` 字段 + `IsDead` 属性
  - `Die()` 开头置位 + 防重复调用（避免 UnitDied 发两遍、PlayerUnit 重复判全员阵亡）
  - `TakeDamage` / `TakeDamageInternal` / `ApplyBuff` / `MoveTo` 开头 `if (isDead) return;`
  - `CanAttack()` 改为 `!isDead && !禁止行动`（卡牌结算用它兜底）
  - `Initialize()` 重置

**③ CardData.Resolve 的攻击加成读取**
- 顺带把 `GetTotalEffectValue` 拆成两个重载，根治 trigger 填错导致静默失效：
  - `(effectType)` = **不限触发时机**，属性类加成统一用
  - `(effectType, BuffTrigger?)` = 指定时机，留给按回合/按事件触发的效果
- `Resolve` 第 3 步 buff 循环原来复用伤害结算**之前**的存活快照，
  现改为每次施加前重新判活（负面 buff 要求双方存活，正面 buff 要求施法者存活）

**新发现的第 4 个问题（已报告用户，未擅自改）**
- `RelicData.技能耐力消耗倍率` 用【增量】填法（滑板鞋 -25% 填 -0.25）
- `BuffData.攻击耐力消耗倍率` 用【绝对乘数】填法（虚弱 +25% 填 1.25）
- 同一概念两种填法，极易填错。已写进 README「已知不一致」和 BuffData 文件头 ⚠ 标记，
  等用户决定统一方向（我倾向统一为增量填法）。
