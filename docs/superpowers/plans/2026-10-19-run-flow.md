# 本局关卡流程 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从新游戏开始，串联两章战斗、独立可领取的战后奖励、事件、休息处与结局，并在一局内继承玩家成长。

**Architecture:** 常驻 `RunFlowController` 管理阶段切换，`RunState` 保存本局数据，`RunRouteData` 引用关卡资产。战斗仍由 `LevelManager`/`GameManager` 执行；奖励由独立服务生成和领取，UI 只展示状态并调用流程接口。

**Tech Stack:** Unity 2022.3.62f3、C#、现有 `LevelData`/`CardData`/`LootSystem`/`EventManager`，Unity Editor 检查与 `dotnet build`。

**Spec:** 本次会话已确认的流程规则；原书面设计稿已按用户要求删除。本计划的“全局约束”保留实施所需的全部具体规则。

## Global Constraints

- 目标分支为 `paqi`；先接入 `main` 已有的两章关卡及战斗 HUD，保留工作区尚未提交的初始牌库改动。不要重新加入已删除的设计稿，也不要修改示例 `Battle.unity` 场景资产。
- 用户要求不代为提交：实施期间不运行 `git commit` 或 `git push`；所有代码、资产和计划保留在本地工作区，最终交付改动清单。
- 新游戏先触发固定事件“实验开始”。每章路线：普通1→事件→普通2→事件→普通3→休息→随机精英→普通4→事件→普通5→事件→普通6→休息→BOSS。每场胜利先显示奖励；精英/BOSS 后没有额外事件或休息。第二章 BOSS 奖励后通关；战败结束本局。
- 每章两个精英关随机选一个，本局选定后保持不变；不新增地图变种随机规则。
- 初始固定技能《推》《跳》，另外 3 个空槽；攻击牌库拳打×4、抛射×2、痛殴×1；防御牌库远跳×2、绊倒×2、格挡×3。重复资产引用表示多张牌。本局获得的牌跨关保留。
- 战后奖励可分别领取且每项最多一次：①混合攻击/防御技能随机展示 3 张不同可获得技能，选 1 张入本局牌库，不占槽、不扣资源；②药水仅有掉落时显示；③精英/BOSS 后从 3 个不同遗物中选 1 个，图像下方显示效果；④精英使耐力/思绪上限及各自每回合回复量各 +2，BOSS 各 +5。可以点击继续放弃未领取项。
- 药水沿用现有 50% 掉落及连续两场未掉则第三场必掉；背包满时保留未领取状态并提示。遗物排除已持有者，候选不足 3 时展示剩余候选。药水效果触发的战斗结束必得遗物独立结算。
- 休息处三选一：回复最大生命值 50%；最大生命值 +2 后回复新上限 25%；或最大生命值 +2、耐力上限 +5、思绪上限 +5。百分比向上取整，生命值不超过上限。
- 血量、牌库、药水、遗物和属性成长跨关；即时耐力、思绪及战斗中灌注的槽位内容在新战斗重置。无退出游戏后的存档/读档。普通事件内容由队友接入；未接入时显示可继续的占位事件。
- 仅实施与流程有关的 UI。战斗 HUD 要显示两个固定技能及三个空槽，且所有五个槽位可操作。所有状态转移、领取和事件完成须防重复执行。

## Review Focus

1. 重复收到 Victory 时只能生成一份奖励并推进一次：Task 5 的 `DuplicateVictoryDoesNotAdvance`。
2. 背包满时药水不消失、不被标记已领取：Task 4 的 `FullPotionInventoryKeepsRewardAvailable`。
3. 本局曾领取的遗物不再进入三选一候选：Task 4 的 `RelicChoicesExcludeOwned`。
4. 跨关恢复遗物不能重复施加即时效果，且不能改写共享 `UnitData`：Task 3 的 `RestoreRunPlayerWithoutSharedAssetMutation`。
5. 关卡或事件完成回调重复触发时不跳关：Task 2 的 `CompleteEventIsIdempotent` 和 Task 5 的 `DuplicateVictoryDoesNotAdvance`。
